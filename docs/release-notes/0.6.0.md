## Added

- `gac sync --remove` deletes the session's block and its profiles, with `--dry-run` to see the
  diff first. It needs no login, so it works after `gac logout`. A `[sso-session]` that
  `gac setup` wrote into the block stays, as plain lines, so the AWS CLI and `[default]` keep
  working. (#69)
- `gac doctor` checks for anything a release from before the rename to gac-redux left behind:
  blocks with `# BEGIN gac sync` markers, a `~/.aws/gac` next to `~/.aws/gac-redux`, and
  `GAC_SESSION` or `GAC_LOG` still set. `gac doctor --fix` rewrites the markers and deletes the old
  directory. (#70)
- Every release asset has a signed build provenance attestation, which
  `gh attestation verify FILE --repo virtualmadden/gac-redux` checks, and the release has a
  CycloneDX SBOM, `gac-redux-0.6.0.cdx.json`. (#72)

## Changed

- `fetchedAt` in `gac list --json` has no fractional seconds, like every other timestamp. (#68)

## Documentation

- [docs/compatibility.md](https://github.com/virtualmadden/gac-redux/blob/main/docs/compatibility.md)
  says what 1.0 keeps stable across 1.x: commands and flags, exit codes, JSON output, the managed
  blocks and environment variables. (#68)
- The README says how to stop using `gac` and uninstall it, and
  [docs/upgrading.md](https://github.com/virtualmadden/gac-redux/blob/main/docs/upgrading.md) what
  changed during 0.x. (#69, #70)

Nothing to do when upgrading, unless a script reads `fetchedAt` with a parser that requires
fractional seconds.
