## Security

- `gac sync --mode process` writes the role name the portal returns into a `credential_process`
  line, which the Rust SDK runs through `sh -c`. A forged portal response could have planted a
  command in `~/.aws/config`. Role names now have to match Identity Center's permission set
  pattern; other names are skipped with a warning. (#91)
- A start URL with a line break, space or other control character is refused. A newline in
  `--start-url` could add lines of its own to `~/.aws/config`. (#89)
- `GAC_REDUX_LOG=trace` no longer prints secrets. Trace output included the role's credentials in
  the console sign-in URL, the SSO access token and the device code. (#92)
- `gac console` sends the role's credentials to `GAC_REDUX_FEDERATION_ENDPOINT` only when it is an
  `https://` URL. (#82)

## Fixed

- `gac select` refuses a `[default]` that already sets `role_arn`, `credential_process`,
  `web_identity_token_file`, `sso_start_url`, `login_session` or static keys, and writes nothing.
  It added the account and role beside them before, and AWS commands kept using the other
  credentials: with `role_arn`, they ran as that role while `gac` reported the selected one as the
  default. (#97)
- A call to AWS gives up after 60 seconds, retries included, and exits with `1`. An endpoint that
  accepted the connection and never answered made `gac` hang before. (#81)
- When AWS can't be reached, the error names the cause and suggests checking the network and
  `HTTPS_PROXY`, instead of printing the SDK's debug output. When the AWS config or credentials
  file can't be parsed, the error names the line and the reason. (#80)

Nothing to do when upgrading, unless a script runs `gac select` against a `[default]` like the one
above: it now exits with `1`.
